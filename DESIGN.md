# SmokeyChatBot design context

The cat is the recognizable character. The chat panel and dashboard should stay clear and quiet so the owner's content remains the point of the interaction.

## Visual system

- Default accent: cobalt `#2f5bff`; hover `#2149dc`. Each site can set one six-digit accent for its widget.
- Dashboard background: white `#ffffff`; secondary surfaces follow semantic muted tokens; main ink `#0f172a`; secondary slate `#475569`; borders `#dce4ef`.
- Typography: Instrument Sans when available, Arial fallback. Short, direct labels. No decorative code or faux terminal language in user-facing UI.
- Controls use 8 px corners, compact panels 12–16 px, and visible 1 px borders. Reserve soft shadows for the floating chat panel and launcher.
- The widget uses its own Shadow DOM stylesheet. Dashboard components are built with React, TypeScript, Tailwind CSS, and shadcn/ui components generated by the official CLI, then customized to these tokens.

## Behavior

- Design variance: moderate. Motion intensity: low. Visual density: medium.
- The mascot may roam on desktop, but the chat panel and important page controls remain readable. On mobile the launcher is stationary.
- Respect reduced motion, keyboard focus, and semantic controls. Loading, error, empty, and quota states must explain what the visitor or owner can do next.
- Default to a conventional launcher when a custom mascot has not been uploaded.

## Assistant and theme extension — 2026-10-27

White is the default main dashboard surface. Neutral secondary areas and cobalt
accents retain the existing identity. Semantic Tailwind/shadcn tokens govern every
control, notice, preview and code example in light and dark mode. A local preference
offers Light, Dark and System without changing the public widget’s brand colors.
Mascot movement is a small bounded signal, accompanied by an explicit status and
polite announcement. Reduced motion uses a settled pose. Static custom mascots and
standard launchers retain the same text feedback.

## Standalone business workspace

Business screens reuse the white-first Instrument Sans/cobalt design and semantic
theme tokens. One responsive sidebar owns business selection and section changes.
On narrow screens its section controls scroll horizontally. The assistant uses one
generation controller across its full page, drawer and modal. Closing an overlay
preserves the active request; changing business discards local request state.

Canonical controls: official shadcn Select, Input, Textarea, Table, Dialog, Sheet
and AlertDialog; shared Field for labels, Notice for persistent feedback and
BusinessMascot for textual, reduced-motion-aware request status. Private custom
mascots load as authenticated blobs. Date ranges use native date inputs with the
business timezone stated. Provider model IDs come from discovery or explicit
input. Connection checks explain their token cost; deletes require confirmation.


## Shared module ownership

`src/features/business` is the canonical business UI for standalone and injected
hosts. `src/sdk` owns the scoped client, request controller, runtime, Shadow DOM
surfaces and overlays. `features/assistant` owns the lower-right mascot and shared
chat drawer/modal; it uses the same draft/current request as the full page.
`hosts/pixelcore` and the standalone workspace own PixelCore-specific transport and
shell navigation. Feature screens do not import standalone authentication.

Embedded surfaces read the host's resolved light/dark mode and contain their own
Tailwind/shadcn CSS and canonical overlay portals. Standalone keeps its document
styles and Light/Dark/System control. The launcher uses 24px desktop / 16px mobile
safe-area offsets, at least 48px controls, and truthful text plus bounded mascot
motion. The drawer is full viewport width on small screens, max 28rem on desktop.
No roaming or dragging was added. Host modal suppression closes the chat without
cancelling the current request. Browser focus/layout acceptance remains pending;
see `docs/SHARED-FRONTEND-VERIFICATION.md`.

`src/styles/shared.css` owns common tokens, controls and mascot motion for both
entry points. `document.css` and `assistant.css` contain only their document/Shadow
host baselines; change shared styling once to update both dashboards.

## Business dashboard refinement — 2026-10-27

The shared business dashboard is an operational surface. Overview uses real report,
connection and quota summaries; Usage has its own call/token summaries, quota
meters, proportional model bars and recorded input/output composition. No simulated
sparklines, savings claims or usage timelines. Supporting tables retain exact values.

Provider and model choices are cards inside the canonical scoped connection dialog.
Provider marks are locally bundled with provenance under `src/assets/providers`.
Connected, verification-needed and default statuses combine icons and text. Rates
are dated reference text-token prices with an explicit single-call example and
an unavailable-price fallback. Provider verification, not the reference catalog,
determines whether a model can be used.

Ask Smokey uses supported report suggestions with icons, draft selection, quiet
hover movement and visible keyboard focus. Suggestions never trigger paid work.
Ctrl/Cmd+Enter submits only with a valid draft, connection and generation permission.
The standalone sidebar footer owns account identity and Light/Dark/System controls;
embedded hosts retain their own account and theme UI.

Runtime ownership: `src/styles/shared.css` maps existing cobalt primary, semantic
card/muted/border/text tokens, plus `--smokey-output` for output-token composition and
`--smokey-success` / `--smokey-success-surface` for verified connections. Light values
are #6e84c4 / #16734b / #edf8f1; dark values are #526d9e / #8ddcb0 / #16382d.
Only movement/width transitions inside `prefers-reduced-motion: no-preference`
are added. Charts remain fully visible with reduced motion.

See `docs/SMOKEY-UI-CONTRACT.md` for canonical ownership, form behavior, pricing
assumptions and data semantics, and `docs/SMOKEY-UI-AUDIT.md` for scoped evidence.

## Credit tracking and compact surfaces — 2026-10-27

Business content fills the available main column with one gutter (16px mobile,
20px small, 24px desktop). Do not add a second centered max-width wrapper around
Smokey pages. Standalone section title/description live in the toolbar as a
breadcrumb; the PixelCore host opts into `pageHeader: "host"` and owns that header.
Other SDK hosts retain the inline breadcrumb by default.

Drawer/modal suggestions are single compact icon rows without descriptions; full
page suggestions retain their descriptive cards. Both use the same draft/controller
and never generate on selection. Appearance choices show Smokey, the private custom
asset (or upload placeholder), and the standard launcher; the live preview follows
unsaved selection, while persistence stays explicit.

Each connection may record manually funded USD credits. Its bar compares that amount
with estimated lifetime costs of recorded Smokey tokens using the existing dated
exact-model rate reference. Missing pricing/token records remain incomplete; they
must not produce a claimed remaining balance. The transform reveal runs once per
value change and respects reduced motion. This is tracking, not provider balance,
credit purchase or spending enforcement. Visible connection data refreshes every
30 seconds without polling during edits or while the document is hidden.

`styles/shadow-properties.css`, imported only by `assistant.css`, supplies Tailwind
property defaults that browsers do not apply from Shadow DOM @property rules.
This preserves utility borders, spacing, shadows and centering in embedded surfaces
without changing the host document or the standalone entry point.

## Session chat and report dashboards

Chat uses circular user/bot avatars and a shared ordered transcript across full-page,
drawer and modal surfaces. Keep the last 30 exchanges and draft in tab-only session
storage scoped to host, business, actor and access context. Scope changes, logout
and expired authorization clear private state. Restoring a request never generates
again automatically; recovery polls the saved ID or reuses its submission key.
Report summary tiles share one subtle cobalt surface, semantic icons and a quiet
hover lift with reduced motion respected. Charts use saved server aggregates, with
accessible values; legacy snapshots explicitly disclose missing chart data.
Tables support scoped search/paging, current-page CSV and fixed-size missing/broken
image placeholders. Product images accompany names and never render as URL text.
